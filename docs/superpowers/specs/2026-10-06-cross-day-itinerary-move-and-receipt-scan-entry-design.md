# 跨天移動景點與收據掃描入口調整規格

## 目標

讓使用者能從行程卡片的「⋯」選單，把景點移至旅程中的任一天；同時從費用 Modal 移除目前不好用的收據掃描按鈕。

## 行程跨天移動

- 卡片「⋯」選單新增「移至其他天」。
- 開啟天數選擇 Modal，列出此行程所有天數，當前天數不可選。
- 使用者確認後，景點保留原開始時間並移到目標日清單末端；目標日原景點順序不變，來源日其餘項目重新編號。
- 以單一 Supabase RPC 原子更新景點 `day_number` 與來源／目標日 `position`，並在伺服器驗證目標天數落在 Trip 起訖日期範圍內，避免搬移半途只更新一邊或寫入不存在的天數。
- 前端先樂觀更新所有天的清單；伺服器失敗時還原並提示錯誤。成功後切換到目標日，讓使用者看到搬移結果。
- 網路中斷時將搬移存入既有 offline mutation queue，並更新離線快照；回線後重播相同搬移操作。
- 來源日或目標日沒有其他景點時仍可搬移；跨日搬移只允許行程有效天數，UI 選項取自目前 Trip 日期範圍。

## 收據掃描入口

- ExpenseModal 不再顯示「掃描收據」按鈕、相機提示或掃描結果 Toast，也不再啟動相機。
- 保留 `lib/receipt-ocr.ts`、`ReceiptScanButton.tsx`、Tesseract 依賴與費用 `receipt_items` 欄位，以便日後重新評估掃描體驗。
- 費用 Modal 現有商品明細的檢視／手動編輯能力維持原狀。

## 驗收

- 搬移後來源日與目標日的項目和位置正確，原開始時間與其他欄位保留。
- RPC 失敗時 UI 資料復原；離線時更新本機快照並排入 `move-day` mutation。
- Timeline 卡片選單可開啟日選擇器，當前日不可搬移至自身；成功後切換到目標日。
- ExpenseModal 不渲染掃描按鈕或相機提示，費用商品明細仍可手動操作。
- 全套 `npm test -- --run` 與 `npm run type-check` 通過。

## 方案決策

採卡片更多選單加天數 Modal，不採跨 Day 拖曳（專案已移除 DnD），也不採複製景點。資料庫端使用單一 RPC，搭配 optimistic state 與離線重播。
