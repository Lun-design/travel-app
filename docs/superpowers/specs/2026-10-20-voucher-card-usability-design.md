# Phase D：票券卡片可讀性、離線狀態與空白提示

狀態：實作及本機驗證完成（921 項測試、TypeScript、build、verify:build 通過）；尚未提交／部署／實機驗收。

## 範圍與不變事項

完成 UX-07、UX-08 及 UX-14 的票券部分。不改票券分類、過期判定、排序、綁定與刪除規則；保留縮圖、大圖預覽、編輯、新增及離線備用入口。無 DB schema 變更，不自動提交或部署。

## 方案比較

1. **建議：卡片就地操作、沿用現有檔案服務。** 預約編號旁複製，每張卡片顯示此裝置的真實快取狀態；需要時由使用者手動下載單張票券。降低找錯編號風險，也不增加開啟頁面的下載量。
2. 自動批次下載所有票券：使用者操作較少，但會消耗頻寬與裝置空間，本階段不採用。
3. 只在既有大圖視窗顯示狀態：改動較小，但仍必須逐張開啟才能檢查，不符合本階段目標。

## 卡片資訊與點擊行為

- 移除列表上方與卡片分離的編號複製按鈕群。
- 每張卡片於預約編號旁提供「複製」，沒有編號不顯示空按鈕；編號可長按／選取文字。
- 沿用 `copyVoucherReference`，成功提示「預約編號已複製」，失敗保留手動複製方式。
- 複製與離線操作不觸發大圖預覽；避免把互動按鈕嵌在另一個 Pressable 裡。
- 縮圖／主要預覽入口、編輯、綁定、刪除保留；手機操作列可換行，不裁切按鈕。

## 離線狀態與下載

- 以現有 `VoucherFileStore`、`getVoucherFileKey`、帳號＋行程＋票券＋file_path 檢查實際本機檔案；不可使用 DB 布林值或跨裝置共享「已下載」。
- 顯示「檢查中」、「已離線備用（此裝置）」、「尚未儲存離線備用」、「無法確認」；不支援的平台顯示不支援提示，不誤稱尚未下載。
- 尚未儲存時提供卡片內「儲存離線備用」按鈕，重用 `saveVoucherOffline` 的驗證與儲存流程，不新增另一套下載規則。
- 手動逐張下載，不在載入頁面時自動批次下載。送出即 loading／同步鎖防連點，失敗提示且可重試；成功後再次檢查快取才能標示可用。
- 沿用大圖視窗原下載能力；視窗關閉後重新檢查卡片狀態。頁面回到前景時重新核對快取，避免清快取後保留舊成功標籤。
- 檔案路徑、帳號／行程改變時立即失效舊狀態。舊檢查／下載結果不得覆蓋新卡片；卸載或切換 scope 取消下載，清理 listener 及 Blob URL（若有建立）。
- 清楚說明僅存此裝置、登出可能清除，保留現有隱私與清理機制。

## 空白、篩選與錯誤分流

- 載入中：保留 header、分類與新增入口，不暫時宣稱沒有票券。
- 真正空清單：顯示新增第一張票券引導，按鈕開啟原新增 Modal。
- 有資料但分類不符合：顯示篩選無結果及可用的清除篩選入口；不顯示「目前沒有票券」。
- 只有已過期票券且預設隱藏時：提示有已過期票券，提供開啟既有過期開關的入口。
- API 載入失敗：保留已顯示資料，提示可重試；無快取時也不能冒充真正空清單。
- 離線：顯示正在使用已載入／快取資料；不能由目前空陣列斷言雲端沒有資料。原有已備用檔案仍可開啟。
- 清除篩選恢復原預設（全部分類、隱藏過期）；若僅剩過期資料，顯示對應的展開入口。

## TDD 與驗收

1. 多張不同編號，各卡片複製正確值；無編號不顯示；不觸發預覽；clipboard 失敗不崩潰。
2. 實際 cache hit/miss/exception 與不支援平台狀態正確；切帳號、trip、file_path 及清快取後不沿用舊結果。
3. 連點下載只送一次；失敗不顯示已儲存；成功後讀回檔案；離線不送下載請求。
4. 舊下載／檢查回應及卸載後結果不能寫入新 scope；前景 listener 清理。
5. 載入中、真空、分類無結果、僅過期、離線及 API 錯誤各有正確提示與可用 handler。
6. Phase B 的分類／刷新／跨行程競態保護測試持續通過。
7. 全量 `npm test -- --run`、`npm run type-check`、`npm run build`、`npm run verify:build` 通過後才交付；實機驗收另列，不由測試代替。
