# 第一階段：分帳結清與刪除防誤觸

日期：2026-10-20。對應 UX 追蹤清單 UX-01。

## 範圍

只調整分帳的確認互動，不改既有金額算法、結清紀錄結構或 DB 權限。

1. `ExpenseList` 的逐筆「結清此筆」先開確認視窗。
2. `ExpenseList` 的費用刪除先開確認視窗。
3. `SettlementCard` 的歷史結清紀錄刪除先開確認視窗。
4. 既有「標記為已結清」視窗保留，補上僅記帳、不實際付款的說明。

## 互動規格

### 逐筆結清

- 第一次點擊僅讀取該筆歷史結清紀錄並預覽，不新增紀錄。
- 預覽沿用 `createExpenseSettlementTransfers`，扣除已完成的部分結清；不可拿原始總額或均分額當剩餘應轉額。
- 列出費用名稱、各轉出／轉入成員的既有頭像與姓名、金額及原始幣別。
- 顯示「僅記錄結清，不會實際轉帳；請確認款項已完成支付」。
- 可取消；唯有「確認記錄結清」才呼叫既有 `settleExpense`。
- 預覽讀取失敗時不提供可提交的舊金額；提供重試與取消。
- 確認期間資料若變更，必須重新取得並檢查預覽，不默默提交與使用者所確認不同的金額。真正多人同時寫入的交易安全需另行評估，不宣稱 UI 確認能取代 DB 交易。

### 費用刪除

- 明確顯示費用名稱與金額，提示刪除後會重新計算分帳。
- 第一次點擊、取消、背景／返回關閉都不呼叫刪除 API。
- 正式確認才交回既有 `onDelete`，不自行繞過父層同步流程。

### 歷史結清紀錄刪除

- 顯示付款人、收款人、幣別、金額與日期。
- 提醒「刪除的是記帳紀錄，不會撤銷真實轉帳；剩餘應付會重新計算」。
- 確認後才呼叫既有 `deleteSettlementRecord`；成功後沿用父層更新餘額。

### 共通防護

- 提交前檢查目前行程、登入使用者及目標是否仍有效。
- 同步鎖在事件進入時生效，不僅依賴下一次 React render 的 disabled。
- 提交中禁止重送與切換對象，成功關閉；失敗保留原對象、顯示可重試錯誤。
- 行程／帳號切換及關閉後的舊非同步回應不得覆蓋新視窗。
- 沿用既有奶茶配色、頭像元件及手機留白，內容可捲動，主要操作可見。
- 未有使用者要求前，不自動合併、推送或部署。
