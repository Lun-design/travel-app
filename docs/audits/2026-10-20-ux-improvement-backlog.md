# 全站使用者體驗優化追蹤清單

建立日期：2026-10-20（Asia/Taipei）。

## 目的與執行方式

記錄本輪程式碼 UX 盤點的所有發現，逐項設計、測試、實作與驗收，避免一次大改熟悉的流程。這是程式碼盤點，不代表每一項都已在正式環境實測重現。

狀態：待處理 → 規格就緒 → 實作中 → 本機驗證通過 → 已部署 → 使用者驗收完成。

「本機驗證通過」不等於「已部署」；未確認的執行期問題先以失敗測試重現。完成後記錄測試指令、結果與實機驗收，不以口頭宣告代替證據。

## 不變的產品底線

- 保留既有景點、費用、分攤、結清、票券、打包與成員資料，不清空或重新建立資料。
- 原有可用入口保留；折疊、篩選、新摘要不應讓原功能消失。
- 不改寫使用者設定的時間，不重新平均分攤費用，不把分攤額當成尚欠款。
- 保留現有頭像及姓名備援、草稿、復原、離線與跨裝置同步能力。
- 草稿、離線檔案及快取要明確標示裝置範圍，不冒充已同步雲端資料。
- 結清只是記帳，不代表真實銀行轉帳，也不得觸發付款服務。
- DB schema、權限、登入及「所有人」勾選語義的變更須獨立設計，確認 migration 與相容策略後才實作。
- 每個批次先補針對性失敗測試，再做最小修正；完成全套測試與型別檢查。涉及正式版 UI 時亦建置檢查。
- 不自動 commit、push、部署或套用正式資料庫 migration。

## P0：防止誤解與誤操作

### UX-01 分帳結清與刪除防呆

狀態：本機驗證通過（852 項測試、TypeScript、正式版建置與 PWA 檢查）；尚未部署／使用者驗收。第一個實作批次。

依據：`src/components/ExpenseList.tsx` 的逐筆結清直接呼叫 `settleExpense`；費用刪除直接執行 handler。`src/components/SettlementCard.tsx` 的歷史紀錄刪除直接呼叫 `deleteSettlementRecord`。

改善：結清前預覽費用名稱、付款人／收款人頭像及姓名、幣別與剩餘結清金額，明確寫「僅記錄結清，不會實際轉帳」。刪除前顯示對象與影響，取消不寫入。歷史紀錄刪除須提醒會重新計算餘額。

驗收：首次點擊不寫 DB；取消／關閉不寫 DB；確認僅送一次；送出中不可再次送出或切換確認對象；失敗保留對象與可重試提示。部分結清預覽不得直接使用原分攤額。原分帳算式不變。

### UX-02 票券篩選、過期狀態與資料一致性

狀態：待重現與實作。

依據：`src/components/VouchersPanel.tsx` 同時保存來源資料與篩選結果；過期開關 `setShowExpired` 後立即執行依賴舊狀態的 `selectCategory`；載入流程可重建未篩選清單。

改善：以單一來源資料搭配分類／過期狀態推導顯示列表，避免分開維護不一致的結果。

驗收：第一次點擊過期開關就正確更新；連點與切換分類不需要多按一次；新增、編輯、刪除與同步後維持目前篩選；切換行程不殘留前一行程資料。

### UX-03 首頁行程狀態正確顯示

狀態：待處理。

依據：`src/app/index.tsx` 的 `daysUntil` 只根據開始日期顯示倒數或「旅程進行中」，未使用結束日期。

改善：區分即將出發、今天出發、進行中、已結束。

驗收：未來、出發當日、行程中、結束當日與結束後的狀態正確；同一天來回可用；使用日期字串的日曆語義，不因 UTC 轉換誤差跳日。

## P1：減少操作與查找成本

### UX-04 打包清單的新增分類與檢視篩選分離

狀態：待設計。

依據：`src/components/PackingPanel.tsx` 的分類列僅更新新增項目的 `category`，清單仍渲染所有分類。

改善：明確區分新增分類與列表檢視；提供分類、未完成、我的項目篩選，保留查看全部。

驗收：切換檢視不偷偷變更新增分類；分類新增仍正確；切換篩選不修改資料；明確定義「我的項目」是否包含所有人項目。

### UX-05 所有人打包項目的完成語義

狀態：待獨立設計，不直接改 DB。

依據：`assigned_to_all` 使用成員頭像組合，但項目仍只有一個共用 `is_checked`。

改善：先明示目前是共用確認，避免被理解為全員各自完成。若升級成每人確認，需另定完成度算法、成員加入／退出、舊資料轉換與離線同步。

驗收：畫面文字與真實狀態一致；舊有勾選不被擅自轉成每人都完成；新增能力不能破壞共用項目。

### UX-06 重複打包項目的明確回饋

狀態：待處理。

依據：`PackingPanel.add` 發現重複項目時會清空輸入並返回，沒有說明。

改善：提示「此項目已存在」，定位或高亮既有項目；不新增重複資料。

驗收：空白、大小寫、護照同義名稱遵守既有去重規則；不誤標新項目；手機與桌面均有可見回饋。

### UX-07 預約編號複製按鈕回到所屬票券

狀態：待處理。

依據：`VouchersPanel` 的 `reservationCopyButtons` 集中在列表上方，與票券卡片分離。

改善：每張卡片在預約編號旁直接提供複製入口與成功提示，沿用既有剪貼簿備援。

驗收：多張不同編號不會複製錯張；缺編號不顯示空按鈕；點複製不誤開預覽；失敗仍能手動選取文字。

### UX-08 票券卡片直接呈現離線可用狀態

狀態：待處理。

依據：離線可用資訊在 `VoucherPreviewModal` 與 `TripPreparationOverview`，票券列表沒有逐張標示。

改善：每張卡片標示已離線備用、尚未下載或無法確認；提供沿用現有流程的下載入口。

驗收：以實際裝置快取判斷，不靠曾點過下載的布林值；失敗不能顯示成功；登出／清快取後可重新檢查；不同裝置的狀態不混用。

### UX-09 分帳首頁的個人摘要與資訊層級

狀態：待設計。

依據：`BudgetDashboard` 先渲染預算輸入與統計，`ExpensesPanel` 在其後才顯示費用卡片。

改善：優先呈現我的剩餘應付／應收與總支出，預算編輯及圖表可折疊但保留入口。

驗收：沿用既有含結清紀錄的餘額資料，不創立第二套算法；無款項顯示已平衡，不顯示「應收 0」；原預算設定及圖表均可取得。

### UX-10 費用列表就地篩選

狀態：待設計。

依據：`ExpenseList` 顯示費用陣列，缺少列表內的成員／待結清／類別篩選。

改善：與我有關、待結清、類別篩選與清除條件；保留全行程搜尋。

驗收：篩選不修改金額及結清狀態；若顯示小計須標清楚「篩選結果」，不能與整趟總額混淆；空結果提供清除篩選入口。

### UX-11 時區改為地區選單，保留進階 IANA

狀態：待設計。

依據：`TripSettingsModal` 要求手動輸入 IANA 時區，例如 `Asia/Tokyo`。

改善：常用地區的中文選單，原始 IANA 放進階選項，保留既有合法自訂值。

驗收：不改寫原景點時間；日本／台灣／韓國及含夏令時間地區正確映射；非預設清單的既有值不被重設；不推定整個國家永遠只有一個時區。

## P2：全站一致性與可及性

### UX-12 登入頁補齊自助與正式環境呈現

狀態：待設計。

依據：`src/app/login.tsx` 沒有忘記密碼與密碼顯示切換，正式版 UI 包含測試帳號範例。

改善：補密碼顯示切換與正式環境測試提示管理；忘記密碼另核對 Supabase redirect 與重設流程後實作。

驗收：不破壞登入、註冊、重寄驗證信及分享頁導回；密碼預設隱藏；重設流程不洩漏帳號是否存在；錯誤清楚且不困在 loading。

### UX-13 手機點擊範圍與語義標籤

狀態：待分批改善。

依據：部分主題／貨幣／結清按鈕的尺寸僅 30～36px；打包勾選與名稱是分離入口。

改善：常用動作提供至少 44px 可點區域；打包名稱／主要列可協助勾選，但頭像指派與刪除維持獨立；補 checkbox 的 checked／disabled 語義與按鈕名稱。

驗收：不誤觸旁邊動作、不一點觸發兩次；鍵盤與螢幕閱讀器可操作；忙碌與停用狀態可辨識。

### UX-14 空白、篩選無結果與載入失敗分流

狀態：待分批改善。

依據：票券篩選後清單為空仍顯示「目前還沒有預約或票券」；不同模組錯誤呈現不一致。

改善：區分從未新增、條件無結果、載入失敗、離線只有快取；分別提供新增、清除篩選、重試或連線說明。

驗收：有資料但被篩掉時不能暗示全部不存在；失敗不清空已顯示資料；每個提示按鈕具備可用 handler。

### UX-15 表單未儲存保護一致化

狀態：待逐表單設計。

依據：景點與費用已使用 `useFormDraft`；個人資料、建立行程與行程設定尚未統一。

改善：先補關閉／返回的未儲存確認；需持久化的文字表單沿用現有 account/trip scope。二進位頭像不可直接存入 localStorage 或假稱可跨裝置恢復。

驗收：取消保留輸入、放棄才清空；保存成功清理正確草稿；帳號／行程隔離；背景更新不重設正在編輯的內容；不錯誤恢復舊伺服器版本。

### 批次 A 本機交付內容

- 費用結清先載入剩餘款項與頭像預覽；確認前不新增結清紀錄。
- 費用刪除及歷史結清紀錄刪除均需確認；取消、背景及返回關閉不寫入。
- 直接確認事件以同步 ref 鎖防止連點；舊確認視窗不得確認更新後、尚未看過的資料。
- 逐筆結清提交前重讀 DB 費用及歷史紀錄；與使用者預覽不一致就中斷並要求再次確認。
- API 已成功但父層畫面刷新失敗時，不把結清標成可重新送出的失敗。
- 仍需單獨評估多人完全同時寫入的 DB 交易／唯一性保護；本次讀取比較不是原子交易。
- 主要新增互動測試：`tests/settlement-safety-ui.test.ts`（15 項）；API 測試含 guarded path 成功與變更阻斷案例。
